⑤ How one review flows over time

The same workflow as a sequence — who talks to whom, in order, with the Q&A loop, the confidentiality boundary, and the two human gates.
sequenceDiagram
    actor R as 👤 Referee
    participant A as 🤖 refereekit
    participant P as 📄 PDF (local)
    participant L as 🧠 LLM (zero-retention)
    participant X as 🔎 Exa
    participant M as 🗄️ Memory
    R->>A: "review this paper"
    A->>P: extract text, figures, equations
    A->>L: summarize (manuscript OK)
    A->>X: search related work (topics only)
    A-->>R: summary + literature context
    loop Q&A until satisfied
        R->>A: a question
        A->>L: answer (manuscript OK)
        A->>P: verify each anchor — PASS/FAIL/FLAG
        A-->>R: verified answer → live HTML
    end
    R->>A: form verdict
    Note over R,A: GATE 1 — you decide
recommend · venue · major/minor
    A->>M: recall your style (notes only)
    A-->>R: draft report in your voice
    R->>A: choose per-section detail
    Note over R,A: GATE 2 — you choose lengths
    A-->>R: final report + editor letter
    A->>M: store verdict + style notes (no manuscript)
The manuscript reaches L (zero-retention) and P (local) only — never X or M. Facts are verified against the PDF at every Q&A turn, not served from memory.

⑥ Why it's built this way — the intentional decisions

Six choices that shape everything above. Each trades a little extra effort for a property we deemed non-negotiable.

1Portable core, thin glue

Value lives in refereekit/, not the harness. Leaving Claude Code for pi.dev or a bare CLI is a ~1-day glue rewrite, not a rebuild. Lock-in is small and localized by design.

2Confidentiality is architectural

Manuscript text goes only to a zero-retention LLM API — never to Exa or the memory store. A guard module rejects any egress input that overlaps the paper; the LLM client fails closed if the endpoint isn't marked zero-retention.

3Verification is inline, typed

Every factual anchor is checked at production time, not in a final pass. Mechanical anchors return PASS/FAIL deterministically; semantic claims always FLAG for you — never silently accepted.

4Two human gates, resumable

You decide the verdict and per-section detail. Both persist to state.json, so a review can stop after Q&A and resume later without losing context.

5MemoryStore port + adapter

SQLite now, mem0 later via one config line. Memory stores only your style and verdict patterns (keyed by venue) — never manuscript content — behind a swappable interface.

6Phased build, loop last

SP-A → B → C → D. The runnable deterministic core ships first (built); drafting, cross-paper memory, and the fully-standalone embedded agent loop follow — the highest-effort piece deferred last.

Status: SP-A (Phase 1) is built, tested, and merged. SP-B/C/D remain as future spec → plan → build cycles.
